Initier un paiement via l’API marchand

Avant cet appel, ajoutez votre agrégateur, configurez votre webhook marchand, créez une clé dans Clés API et réussissez un paiement dans Tester paiement.

VOTRE_CLE_API_FIDELITYPAY est la clé affichée lors de sa création. Gardez-la uniquement sur votre serveur.

VOTRE_REFERENCE_UNIQUE identifie cette tentative dans votre système, par exemple commande-1042-paiement-1. Réutilisez-la après un timeout pour éviter de créer un second paiement.

{{ initiateCurl }}

Conservez paymentId. Pour WAVE_REDIRECT ou HOSTED_CHECKOUT, ouvrez paymentUrl. Pour MOBILE_MONEY_REQUEST, le client confirme sur son téléphone. Pour ORANGE_CI_OTP, suivez nextAction.

Traiter les notifications webhook

FidelityPay envoie une notification signée à l'URL HTTPS configurée dans Intégration.

POST VOTRE_URL_WEBHOOK
X-FidelityPay-Event: payment.success
X-FidelityPay-Signature: sha256=SIGNATURE_HEXADECIMALE

{
  "paymentId": "fp_123456",
  "event": "payment.success",
  "status": "SUCCESS",
  "amount": 5000,
  "currency": "XOF",
  "operator": "WAVE",
  "country": "SN",
  "providerPaymentId": "provider-789",
  "failureReason": null,
  "updatedAt": "2026-06-20T12:00:00"
}

À la réception

  1. Lisez le corps brut de la requête avant de parser le JSON.
  2. Calculez son HMAC-SHA256 avec le secret webhook, encodez-le en hexadécimal et préfixez-le par sha256=.
  3. Comparez le résultat à X-FidelityPay-Signature avec une comparaison à temps constant.
  4. Ignorez les doublons déjà traités pour le même paymentId et le même événement.
  5. Enregistrez le nouvel état du paiement dans votre système.

Statuts de paiement

  • PENDING: le payeur doit terminer ou confirmer le paiement.
  • REQUIRES_ACTION: exécutez l'action indiquée, par exemple un OTP.
  • SUCCESS: paiement confirmé.
  • FAILED: le fournisseur a refusé ou n'a pas pu terminer le paiement.
  • CANCELLED: le payeur a annulé le parcours.
  • PENDING_RECONCILIATION: FidelityPay attend une confirmation fiable du fournisseur.
